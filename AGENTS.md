## Commands

- `npm run dev` - dev server (localhost:3000)
- `npm run test:unit` - focused foundation unit tests (includes `src/test/messages-parity.test.ts`: every `messages/<locale>/<ns>.json` must have identical key sets and ICU placeholder names across en/ko/zh)
- `npm run build` - production build; **must pass before any work is considered done**
- `npm run lint` - ESLint
- CI (`.github/workflows/ci.yml`) runs lint, `next typegen` + `tsc --noEmit`, unit tests, and the production build on every PR/push to `develop` and `main`. The dependency audit job (`npm audit --omit=dev --audit-level=high`) is blocking since the 2026-10-24 wagmi 3 upgrade took production high/critical advisories to 0; a new high advisory fails the PR.

## Git flow

- Branches: `main` = Vercel production, `develop` = integration branch (Vercel preview). Both must always build (`npm run build` + `npm run lint` green); never commit broken work to either.
- Day-to-day work branches off `develop` and goes back through a PR; direct commits to `develop` are for the solo-maintainer fast path only (docs, small fixes). Nothing is committed directly to `main`.
- Branch names: `<type>/<kebab-slug>` - types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test` (e.g. `feat/bounty-detail`, `fix/header-nav-active`).
- Commit messages: Conventional Commits, matching the existing history - `<type>(<scope>): <summary>` with lowercase imperative summary, no trailing period (e.g. `feat(admin): session-local interactive admin managers`). Scope is optional for `docs`/`chore`.
- One logical change per commit; never mix a feature with unrelated formatting or lockfile churn.
- Feature PRs target `develop`. Recent history (#15-#22) merges them with a merge commit; if a PR is squashed instead, the squash title must itself be a valid Conventional Commit line. Delete the branch after merge.
- Releases are a PR from `develop` to `main` merged with a **merge commit** (no squash/rebase), so the two branches keep a shared history and `develop` never diverges from `main` (e.g. release PR #19).
- Never force-push `main` or `develop`. Force-push (`--force-with-lease` only) is allowed solely on your own feature branches.
- Never rewrite published history, revert/stash/delete others' work, or push without the build and lint passing locally.
- `package-lock.json` changes only appear in commits that intentionally change dependencies (`chore(deps): ...`).

### Session rules

- Start every agent session by pointing it at the task's Figma node (table above) and `docs/design.md`; follow the recipes there instead of inventing variants.
- One branch per lane task (`feat/<lane>-<slug>`); never let an agent commit another lane's files as drive-by changes.
- Doc-sync duty: adding a component updates the inventory in this file; adding a visual pattern updates `docs/design.md`; resolving/creating a design gap updates `docs/figma/design-gaps.md` - in the same PR.
- Before ending a session: `npm run lint` + `npm run build` (+ `npm run test:unit` when touching foundation/auth/wallet/admin logic).
- Agent runtime state (`.gjc/`, `artifacts/`) is gitignored - never commit it; never commit `.env.local`.

## Styling rules

- **Tailwind utility classes only.** No CSS Modules, no styled-components, no `style={}` props, no new `.css` files.
- **Reduced motion:** anything that animates or moves content (`animate-*`, `transition-*` on transform/position/size) carries `motion-reduce:animate-none` / `motion-reduce:transition-none`; the three `loading.tsx` skeletons use `animate-pulse motion-reduce:animate-none`. Color/shadow transitions (`transition-shadow`) are exempt (see `docs/design.md`).
- The single CSS file is `src/app/globals.css`. Design tokens live there in the Tailwind v4 `@theme` block
  (`--color-*`, `--font-*`, `--radius-*`, ...) and are consumed as utilities (`bg-surface`, `text-accent`, ...).
- New color/spacing/typography values from Figma go into `@theme` as tokens first - never hardcode hex values in components.
- **`docs/design.md` is the design-system contract** - token semantics, radius/typography roles, and copy-paste recipes (buttons, cards, badges, focus ring, empty states). Follow its recipes instead of inventing variants; new patterns get added there in the same PR.

Instead `src/proxy.ts` rewrites every in-locale miss - a path matching no entry of `lib/locale-routes.ts localeRoutePatterns` (kept equal to the `src/app/[locale]` page files by `src/test/locale-routes.test.ts`; add a page → add its pattern) or a detail URL whose id cannot exist (`lib/detail-id.ts detailMayExist`: id shape in both modes - mock slug `^[a-z0-9-]+$`, api UUID for bounties/notices, nickname shape minus the reserved route words of `lib/nickname.ts` (`me`, `check-nickname`, `admin`, `new`, `edit`, plus the `withdrawn_` prefix of anonymized withdrawn accounts) for members - and the fixture registry in mock mode) - with `NextResponse.rewrite(url, { status: 404 })` to the STATIC `src/app/[locale]/page-not-found` page (prerendered per locale, `noindex`, no canonical): status 404, full SSR document with the right `<html lang>`, localized `<h1>`/title. The page's own path is not in the route table, so a direct visit is a 404 too. Because the page is prerendered the 404 carries the static `Cache-Control: s-maxage=31536000`; a deploy purges the CDN cache, and api-mode ids that fail the shape check can never become valid. The proxy never calls the BE: a per-request existence probe would block SSR on BE latency with no timeout and double the calls against the 600/min public-read IP throttle. `[locale]/not-found.tsx` remains the client-rendered boundary for the residual case (a well-formed but missing bounty/notice UUID or member nickname in api mode: status 404 + `noindex`, bare SSR body until hydration); the `[id]` layouts/pages call `validateDetailId` before any fetch and keep their own existence check (`notFound()` before streaming). The root `app/not-found.tsx` (`/_not-found`) only serves paths outside the `[locale]` routes (proxy-excluded static-extension paths such as `/ko/missing.png`): a minimal, fully static English document (own `<html lang="en">`, fonts, `globals.css`, no Header/Footer) whose `RootNotFoundCopy` swaps to the URL's locale after hydration. **Rule: never read `headers()`/`getLocale()` (or any locale-less next-intl API: `getTranslations()`/`useTranslations` without an explicit locale, the server `NextIntlClientProvider`, `AppShell`/Header/Footer, `setRequestLocale`) in the root `app/layout.tsx` or the root `app/not-found.tsx`** - both are part of every page's render, so one request-time read turns EVERY route dynamic (`private, no-store` instead of `s-maxage=31536000`; this happened once: 62 → 5 prerendered routes). After touching either file, compare `.next/prerender-manifest.json` route counts against the previous build (mock mode: 66 routes incl. `/_not-found` and the three `/<locale>/page-not-found`). The 404 rewrite response carries Next's internal `x-middleware-rewrite: /<locale>/page-not-found` header: Next's router adds it after the proxy returns (`resolve-routes.js`), so the proxy cannot strip it and `next.config.ts headers()` cannot delete headers; it only reveals that internal path and is left as is.
- SEO surface: `metadataBase` from the validated runtime origin, per-page `alternates` from `i18n/alternates.ts localeAlternates(locale, href)` (canonical = the page's own localized URL, `languages` = the same page in every locale; every page/layout with metadata sets it because a child's `alternates` replaces the `[locale]` layout's locale-home value; 404 metadata sets `alternates: {}`), root openGraph/twitter cards, per-detail og title/url overrides, code-generated 1200×630 `src/app/[locale]/opengraph-image.tsx` (ImageResponse; inlines hero-gradient token hex values because Satori cannot read CSS vars; `alt` and the three text lines come from `common.site.og.*` - the alt through `generateImageMetadata({ params })`, so the image URL carries the `social` id: `/<locale>/opengraph-image/social`; `next.config.ts redirects()` 308s the earlier id-less `/<locale>/opengraph-image` there for cached scrapers - redirects run before the proxy's 404 rewrite), `src/app/sitemap.ts` (registry-derived URLs), and `src/app/robots.ts` (disallows `/admin`, `/account`, `/applications`, `/agents$`).
- Design-required gaps (auth states, form errors, confirmations, pagination, real assets) are tracked in `docs/figma/design-gaps.md` + the FigJam board linked there.

## i18n

- Locales `en`/`ko`/`zh` (`src/i18n/routing.ts`, `localePrefix: "always"`), one JSON file per namespace per locale under `messages/<locale>/<ns>.json`; add a namespace to `src/i18n/messages.ts namespaces` when a file is created. `src/test/messages-parity.test.ts` enforces identical key sets and ICU placeholder names across the three locales - every new key lands in all three files in the same PR.
- Navigation always goes through `@/i18n/navigation` (`Link`, `useRouter`, `usePathname`, `redirect`, `getPathname`), never `next/link`/`next/navigation`.
- Client message budget: the shell provider in `app/[locale]/layout.tsx` passes `messages={pickMessages(messages, shellNamespaces)}` (`common` only - Header/Footer/AuthArea/UserMenu/LocaleSwitcher/GoogleLoginButton/ConfirmDialog/Toast/error.tsx all read `common.*`). A segment whose client islands read anything else wraps `children` in `layout/PageMessages namespaces={[...]}` from its own `layout.tsx` (`bounties` → bounties+agents, `applications` → account+bounties, `agents` → agents+account+bounties, `members`, `notices`, `signup`, `admin`, `auth/callback` → signup); each of those layouts calls `setRequestLocale` first. When a client component starts reading a new namespace, add it to that segment's layout - a missing namespace surfaces as `MISSING_MESSAGE` in the console/build output. Server components are unaffected (`getTranslations` reads the full request messages).
- Formatting: `src/i18n/request.ts` fixes `timeZone: "UTC"`; dates/numbers shown to users go through `useFormatter()` (client) / `getFormatter()` (server), never `toLocaleString` or template literals - models keep raw ISO strings / numbers. `lib/{members,hall-of-fame}.ts` (client-bundled too, so no `next-intl/server`) format API dates with `lib/api/codecs.ts formatUtcDate(value, locale, options)`, which pins the same UTC zone (`src/test/members-data.test.ts` runs under a UTC+14 `TZ`).
- The locale proxy (`src/proxy.ts`) matcher must stay a literal (Next parses it at build time). It excludes `_next`, `_vercel`, `media`, `api/` (the same-origin `/api/auth/*` cookie-mode auth proxy), the unprefixed `/skill.md` and a fixed static-file extension list only, so dotted paths such as `/members/ninja.inj` still locale-redirect (`src/test/proxy-matcher.test.ts`). It wraps next-intl's middleware with the in-locale 404 rewrite (unknown paths + impossible detail ids) described under "Routing / 404".
